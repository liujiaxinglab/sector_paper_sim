## 一、项目定位与总体目标

`sector_paper_sim` 是 `sector_radar` 的独立下游轻量模拟盘仓库。本项目不做复杂因子挖掘、不接入实盘券商接口、不改造上游数据源，仅通过严格确定的日频撮合引擎，将 `sector_radar` 的四态路由结论转化为标准化的模拟盘净值曲线、成交流水与周度报告。

总体目标：
1. **建立物理隔离的轻量模拟盘底座**：在 `sector_paper_sim` 内独立维护配置、撮合源码、单测与周报输出，对 `sector_radar` 与 `QuantData` 坚持严格只读。
2. **定格确定性撮合口径**：以标准 JSON 锁定初始资金（10 万元）、单行业 1/6 权重上限、100 份整手、万二佣金（最低 0.1 元）、零印花税、现金分红再投及海龟/网格核心参数，杜绝运行期随意调参。
3. **完成 12–18 个月实证跟踪**：在阶段 1 交付完毕后关闭开发 Task 流，每周五例行更新并留存可审计快照，最终以净值、最大回撤与相对 `159330.SZ` 超额收益完成长期检验。

## 二、硬性架构约束

- **物理隔离与写入白名单**：仅允许在 `D:/VibeCoding/Quant/sector_paper_sim/` 目录内新建与修改文件；严禁修改 `sector_radar`、`QuantData`、`KnowledgeBase` 及 `youce_quant_510720_strategy` 下的任何文件。
- **运行环境定格**：统一显式调用 `C:\Users\jxing\.conda\envs\quant\python.exe`，禁用系统默认 `python`，严禁 `pip install`。
- **配置格式定格**：全部配置文件采用标准 JSON，禁止使用 YAML。
- **输出版本化**：`output/` 目录不得写入 `.gitignore`，周度报告与状态快照随本地 Git 留痕（本地提交、不主动推送远端）。
- **客观回执与审阅分离**：各 Task 执行结果仅客观记录文件变更清单、命令与原始输出，不得由执行者自下“验收通过”等审阅结论。

## 三、两阶段工作路线

### 阶段 1｜引擎搭建与首周试跑

- **子规划入口**：[01_阶段1_引擎搭建_子规划.md](01_阶段1_引擎搭建_子规划.md)
- **阶段目标**：通过 4 个紧凑任务（`1t01`–`1t04`），完成独立建仓与参数定格、只读上游数据加载、每日 4 步确定性撮合引擎及单测、以及周报生成与首周端到端试跑。
- **退出准入条件**：
  1. `1t01`–`1t04` 全部完成独立审阅与问题清零；
  2. 全量单元测试通过，资金守恒、整手取整、费率与除息/拆分边界口径无歧义；
  3. 首周真实上游数据试跑可稳定产出 `output/` 周报与账户快照，且多次重复运行结果逐字节一致（去除时间戳字段或锁定基准日后完全确定）。

### 阶段 2｜稳定运行期（12–18 个月周五例行运行期）

- **管理模式切换**：**正式退出开发 Task 流**。不再按开发子任务迭代新功能或事后修改策略参数，仅允许在发现明确账务计算缺陷时按独立缺陷单修复并记录影响范围。
- **每周五例行操作流**：
  1. 在通达信客户端刷新本地日线，并由 `sector_radar` 完成周度亮灯看板与 `watchlist.json` 路由态更新；
  2. 显式使用 `C:\Users\jxing\.conda\envs\quant\python.exe` 运行 `sector_paper_sim` 周度更新脚本；
  3. 检查 `output/` 下生成的当周周度报告与账户状态快照，确认无行情日期滞后或异常报错；
  4. 本地执行 `git add` 与 `git commit` 冻结当周模拟盘运行快照。
- **阶段复盘与硬检验**：
  - 按季度与 `sector_radar` 的双错复盘对齐，核对路由切换时点与策略切换成本；
  - 连续运行 12–18 个月后，基于完整模拟盘账本评估组合总收益、年化波动、最大回撤、相对 `159330.SZ` 超额收益与策略胜率/赔率表现。

## 四、多仓库分工矩阵

| 仓库 | 定位 | 与本仓关系 |
