### 1.3 权威只读数据源与停牌日处理

1. **观察池（1 基准 + 6 行业 ETF）**：基准 `159330.SZ`（沪深300ETF）；行业池（按标的代码字母序遍历）：`159622.SZ`（沪港深创新药ETF）、`510720.SH`（红利国企ETF）、`512400.SH`（有色金属ETF）、`512480.SH`（半导体ETF）、`512880.SH`（证券ETF）、`515790.SH`（光伏ETF）。
2. **日线行情源（`TDX-01`）**：只读加载 `QuantData/raw/tdx/vipdoc_parsed/{symbol}/` 下最新批次 `YYYYMMDD_HHMMSS.csv`。
3. **权威交易日历（QRI `BS-01`）**：
   - 交易日历改由 QRI `BS-01`（BaoStock `query_trade_dates`，仓库实测原始目录 `QuantData/raw/baostock/query_trade_dates/`，对应 `RD-004` 规划口径 `BS-01` 日历）权威驱动，仅以 `is_trading_day == 1` 的日期作为市场交易日推进序列；
   - **严禁以多只 ETF 日期交集充当交易日历**，防止任一 ETF 临时停牌导致全市场交易日被静默吞没；
   - 若检测到某 ETF 最新 CSV 末日落后于全池最新日或目标 `--as-of` 日（`lag_warnings` 非空，属本地数据未刷新而非历史上某日停牌），默认中止推进，仅在显式传入 `--allow-lag` 时放行。
4. **单标的停牌日确定性处理**：当权威交易日历显示 `T` 日开市，但个别 ETF 当日缺 K 线（停牌）时：
   - **盘前公司行为照常处理**：若 `T` 为除息日，现金分红 `shares * cash_per_unit` 照常计入 `cash`；若 `T` 为份额折算生效日，持仓份数与激活网格价位照常按 `factor` 折算；
   - **涉及开盘交易的动作顺延至复牌首日开盘**：包括该标的的除息再投（保留待复投分红金额至复牌首日 Step 1）、路由切换清仓/建网（保留待执行调仓目标，不提前更新为已完成）、海龟开盘买卖及 `C`/`D` 组首日建仓，统一顺延至该标的复牌后首个有效交易日开盘按届时 `open` 价执行；
   - **盘中撮合跳过**：当日跳过该标的 Step 3 盘中网格撮合；
   - **收盘按最近前收估值**：Step 4 使用该标的最近有效收盘价 `last_known_close` 计算市值，并在运行日志与报告中显式标注 `[停牌按前收估值 YYYY-MM-DD]`。
5. **公司行为台账（分红与份额折算）**：统一只读读取 `` `QuantData/reference/etf/corporate_actions/latest/corporate_actions_ledger.json` ``（取代阶段 1 硬编码快照 `20261120/watchlist_dividend_events.json`），集中解析现金分红与份额折算。该文件的精确读取契约（与上游 `sector_radar` 100% 一致）如下：
   - 顶层 `"schema_version": "2.0.0"`，`"as_of": "YYYY-MM-DD"`（schema 版本不符或缺键一律显式抛错）；
   - `"cash_dividends_by_symbol"`：`dict[symbol, list[dict]]`，每条读取 `"ex_date"` 与 `"cash_per_unit"`，同一标的列表按 `ex_date` 升序；
   - `"splits_by_symbol"`：`dict[symbol, list[dict]]`，每条读取 `"effective_date"` 与 `"factor"`（前复权价格乘子，例如 1 拆 2 为 `0.5`；盘前持仓 `shares_new = round(shares / factor)`，网格价乘以 `factor`）。
6. **上游四态路由历史**：统一只读读取 `sector_radar` 的 `` `project_content/journal/regime_history.json` ``。对任意交易日 `T` 与行业标的 `sym`，严格按 `effective_date <= T` 选取最新一条已生效记录作为当日 `target_regime`；`UNRATED` 统一等价映射为 `TRANSITION`。彻底取消 `state.json["next_effective_regime"]` 与墙钟运行时依赖。

## 二、双轨价格口径与无未来函数原则

1. **双轨价格并行**：
   - **原始未复权现货 OHLC**（`TDX-01` CSV）：用于一切成交价撮合、现金扣减/回笼、分红现金计算及每日收盘估值。
   - **前复权连续可比 OHLC**：在原始日线上叠加截至当前计算时点已生效的 `split_events`（`date < effective_date` 乘以 `factor`）与现金分红除息折算（`date < ex_date` 累乘 `(prev_close - cash) / prev_close`），仅用于 `ATR20`、55 日突破线、20 日破位线及 `close_{T-1}` 计算，并按当日 `adj_factor[T]` 映射回 `T` 日现货价格空间（消除了未来分红/拆股对历史日期的回溯漂移）。
2. **严格截止 `T-1` 信号纪律**：
   - 交易日 `T` 的海龟入场/离场信号（`T-1` 收盘确认）与网格开网锁定步长 `ATR20_{T-1} / close_{T-1}` 均严格仅消费 `<= T-1` 的前复权信息，严禁引入 `close_T` 或未来任何事件。

## 三、单日四步确定性处理时序

对自 `2026-11-23` 起的每一个权威交易日 `T`，引擎按标的代码字母序串行执行以下 4 个步骤，严禁乱序或跨步回溯：

### Step 1｜盘前份额折算、除息现金到账与 `open_T` 含佣金复投

1. **份额折算（`split`）**：若 `T == effective_date` 且盘前持仓 `shares > 0`，更新 `shares_new = round(shares / factor)`、`avg_cost_new = avg_cost * factor`；若标的存在激活网格，同步将 `anchor_price` 与挂单价乘以 `factor`、卖单挂单股数除以 `factor` 并四舍五入。
2. **现金分红与含佣金自动再投**：
   - 若 `T == ex_date` 且盘前持仓 `shares > 0`：应得分红 `div_cash = shares * cash_per_unit` 立即计入 `account.cash` 并登记 `DIVIDEND_CASH` 事件；
   - 若 `dividend_reinvest == true`，且该标的在当日 Step 2 **不会**因切入 `TRAP_OFF` / `TRANSITION` 或跨态切换而开盘清仓：
     - 若标的当日停牌（无有效 `open_T`）：将 `div_cash` 记入该标的待复投额度，顺延至复牌首个交易日 Step 1 执行；
     - 若标的正常交易（`open_T > 0`）：以当日 `open_T` 按**标准万二佣金（最低 `0.10` 元）**计算最大可买整手份数 `reinvest_shares`（满足 `notional + max(notional * 0.0002, 0.10) <= div_cash_available` 且 `<= account.cash`）；
     - 若 `reinvest_shares >= 100`：按 `open_T` 买入并扣减 `notional + fee`，记录 `DIVIDEND_REINVEST` 成交；余零资金留存账户现金。当日复投买入股数计入 `bought_today`，受 T+1 约束当日不可卖出。

### Step 2｜开盘 `open_T` 状态切换调仓、网格建网与海龟信号执行

1. **基准对照首日建仓（`C` / `D` 组）**：
   - 自 `2026-11-23` 起尚未建仓的标的，按代码升序以 `open_T` 执行首日买入（`C` 组单标的预算 `min(prev_equity / 6, available_cash)`，`D` 组全仓 `available_cash`，均计提标准万二/最低 `0.10` 元佣金并向下取整 100 股）；遇停牌标的正向顺延至其复牌首日开盘。
2. **`Account A` 路由切换与 `TRAP_OFF` / `TRANSITION` 全额清仓（修复 `ISS-003`）**：
   - 读取截至 `T` 日已生效的目标路由 `target_regime`（`UNRATED` 视同 `TRANSITION`）：
   - **切入 `TRAP_OFF` 或 `TRANSITION`**：只要目标态为 `TRAP_OFF` 或 `TRANSITION`，且当前持仓 `shares > 0`（含因历史停牌顺延的待清仓状态），**必须于当日开盘 `open_T` 100% 清仓卖出全部持仓**（`TRAP_OFF` 记 `TRAP_OFF_LIQUIDATION`，`TRANSITION` 记 `REGIME_SWITCH_EXIT`，按标准计提佣金），同时清空旧海龟/网格状态并置 `active_regime = target_regime`（若停牌则保留待清仓标识顺延至复牌首日开盘）。
   - **跨有效策略态切换（`TREND_UP` ↔ `RANGE_GRID`）**：先以当日 `open_T` 100% 清仓旧策略全部持仓（`REGIME_SWITCH_EXIT`）并重置旧策略内部状态，再按新路由态接续下方初始化。
3. **`RANGE_GRID` 开盘建网初始化（修复 `ISS-005`）**：
   - 适用对象：`Account A` 切入 `RANGE_GRID` 且尚未激活网格的标的，以及 `Account B2` 尚未激活网格的标的（于起算日 `2026-11-23` 或停牌顺延复牌首日触发）；
   - **锁定基准价**：`P0 = open_T`；
   - **锁定步长（前复权 `T-1` 口径）**：`s = max(ATR20_{T-1} / close_{T-1}, min_step_pct)`，其中 `min_step_pct = 0.015`（1.5% 下限，不设 step_max 上限截断，彻底与上游 00_实盘对照与机械基准约定.md 对齐）；
   - **建 50% 底仓**：单行业总预算 `sector_budget = prev_equity * (1 / 6)`，开盘建仓目标资金 `init_budget = min(0.5 * sector_budget, available_cash)`，以 `open_T` 考虑佣金后向下取整至 `100` 股买入底仓并记为 `GRID_INIT_BUY`（计入 `bought_today`，受 T+1 约束当日不可卖）；
   - **构造等差网格价格序列**：严格按**等差公式**布设基准价上下各档挂单（档位总数由对称配置 `grid_levels_each_side` / `total_slices` 对齐 `50%` 底仓与 `50%` 预留现金划分，如单边 4 档对应总 8 份/底仓 4 份）：
     - 下方第 `k` 档买价：`P_{-k} = P0 * (1 - k * s)`（`k = 1, 2, ...`，需 `P_{-k} > 0`）
     - 上方第 `k` 档卖价：`P_{+k} = P0 * (1 + k * s)`（`k = 1, 2, ...`）
4. **海龟信号执行（`Account A` `TREND_UP` 态与 `Account B1` 全标的，修复 `ISS-006`）**：
   - 严格使用截至 `T-1` 收盘的前复权连续序列判断信号（完全对齐 `sector_radar` 55/20 日指标口径，无未来函数），并在 `T` 日 Step 2 按 **`open_T`** 成交（停牌则顺延至复牌首日开盘）：
   - **突破入场**：若当前空仓（`shares == 0`）且 `T-1` 收盘满足 55 日突破（`close_{T-1} >= max(close[T-56 : T-1])`，不含 `T-1` 前 55 个交易日最高收盘价）：
     - 目标买入金额严格按 **`min(prev_equity / 6, available_cash)`** 计算，**彻底禁止任何 `1% ATR` / `risk_fraction` 缩仓**；
     - 计提标准万二（最低 `0.10` 元）佣金后向下取整至 `100` 股整数倍买入，记录 `TURTLE_ENTRY_BUY`（计入 `bought_today`）。
   - **破位离场**：若当前持仓（`sellable_shares > 0`）且 `T-1` 收盘满足 20 日破位（`close_{T-1} <= min(close[T-21 : T-1])`，不含 `T-1` 前 20 个交易日最低收盘价）：
     - 按 `open_T` 全额卖出全部可卖持仓（100% 离场），记录 `TURTLE_EXIT_SELL`。

### Step 3｜盘中等差网格按 K 线阴阳确定性路径撮合

仅针对处于激活态且当日非停牌的 `RANGE_GRID` 标的执行盘中挂单撮合；Step 3 新生成的反向补单统一于次一交易日（`T+1`）起生效，严禁当日内反向来回套利，且当日新买份额（`bought_today`）严禁当日卖出（严格遵守 T+1）。

1. **跳空成交价规则**：
   - 触发买档 `buy_price`（`low_T <= buy_price`）时，成交价 `fill_price = min(open_T, buy_price)`；
   - 触发卖档 `sell_price`（`high_T >= sell_price`）时，成交价 `fill_price = max(open_T, sell_price)`。
2. **K 线阴阳确定性路径（消除先高后低/先低后高歧义）**：
   - **阳线及平盘（`close_T >= open_T`）路径：`open_T -> low_T -> high_T -> close_T`**：
     1. 先执行下降段（`open_T -> low_T`）：按档位由高到低顺序检查已有买单是否满足 `low_T <= buy_price`，可买股数按 `min(slice_budget, available_cash)` 含佣向下取整至 100 股，成交后登记 `GRID_BUY`（计入 `bought_today`）并在 `level + 1` 生成**次日生效**的反向卖单；若现金不足 1 手则停止继续向下触发；
     2. 再执行上升段（`low_T -> high_T`）：按档位由低到高顺序检查已有卖单是否满足 `high_T >= sell_price`，仅可卖出截至昨日已持有的 `sellable_shares`（绝对不卖出当日刚在 Step 2 或下降段新买的份额），成交后登记 `GRID_SELL` 并在 `level - 1` 生成**次日生效**的反向买单。
   - **阴线（`close_T < open_T`）路径：`open_T -> high_T -> low_T -> close_T`**：
     1. 先执行上升段（`open_T -> high_T`）：按档位由低到高顺序检查已有卖单是否满足 `high_T >= sell_price`（仅动用 `sellable_shares`），成交回笼现金并登记 `GRID_SELL`，同时在 `level - 1` 生成**次日生效**的反向买单；
     2. 再执行下降段（`high_T -> low_T`）：按档位由高到低顺序检查已有开盘前已有买单是否满足 `low_T <= buy_price`，成交登记 `GRID_BUY` 并在 `level + 1` 生成**次日生效**的反向卖单（不触发本段刚刚生成的新挂单）。

### Step 4｜收盘估值、账务守恒与标准化落盘

交易日 `T` 全部撮合完成后，以各标的当日原始现货收盘价 `close_T`（停牌标的使用最近已知有效收盘价 `last_known_close`）执行收盘核算：

1. **净值与绩效计算**：
   - `market_value_T = sum(shares_i * close_{i,T})`
   - `equity_T = cash_T + market_value_T`、`nav_T = equity_T / initial_capital`
   - `daily_return_T = equity_T / equity_{T-1} - 1`、`cum_return_T = nav_T - 1`
   - `peak_equity_T = max(peak_equity_{T-1}, equity_T)`、`drawdown_T = equity_T / peak_equity_T - 1`、`max_drawdown_T = min(max_drawdown_{T-1}, drawdown_T)`
   - 计算 A 组相对 B1/B2/C/D 的超额收益 `A_cum_return - X_cum_return`。
2. **双守恒强校验**：
   - 校验每笔成交后 `cash >= 0`、`shares >= 0`；
   - 校验现金变动恒等式 `cash_T - cash_{T-1} == div_cash_T + sum(net_cash_flow_T)` 与权益变动恒等式 `equity_T - equity_{T-1} == (market_value_T - market_value_{T-1}) + cash_delta_T`，绝对误差须 `< 1e-6`。
3. **精简断点与结构化落盘（`project_content/output/`，修复 `ISS-009`）**：
   - `` `project_content/output/nav_daily.csv` ``：追加/幂等刷新每日 5 账户净值、现金、市值、回撤与 A 组超额流水；
   - `` `project_content/output/trades.csv` ``：按 `(date, account, int(trade_id))` 确定性排序导出全量成交明细；
   - `` `project_content/output/state.json` ``：**仅保留增量步进所需的最新截面状态**（当前日期、`last_known_closes`、各账户最新现金/权益/持仓/策略挂单及 `next_trade_id` 计数），**严禁写入全量历史 `daily_records` / `trades` / `excess_history`**；
   - `` `project_content/output/nav_latest.md` `` 与 `` `project_content/output/history/nav_YYYYMMDD.md` ``：输出最新交易日横向报告与不可篡改日期快照。

## 四、可复现性不变式与异常处理

1. **全量重放 vs 逐日增量绝对一致**：
   - 清空 `project_content/output/` 后执行 `run_daily_sim.py --from-scratch --as-of T`，与自 `2026-11-23` 起逐日增量执行到 `T`（即使中间跨多周多次重启），最终产出的 `` `project_content/output/nav_daily.csv` ``、`` `project_content/output/trades.csv` `` 与各账户期末持仓/现金/净值/挂单状态必须 **100% 一致**。
2. **确定性遍历顺序**：
   - 共享现金池的多标的遍历统一按标的代码字母序（`159622.SZ` → `510720.SH` → `512400.SH` → `512480.SH` → `512880.SH` → `515790.SH`）。
3. **严禁静默降级与负现金**：
   - 任一配置损坏、权威日历缺失对应区间、公司行为台账或路由历史缺失对应日期覆盖、或本地 `TDX-01` CSV 缺失/损坏时，必须显式抛错中止，严禁联网抓取或猜测补全；任意买单必须同时满足 `notional + fee <= available_cash`，不足 1 手则放弃本次买入，严禁负现金。
