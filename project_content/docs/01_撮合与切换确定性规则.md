## 二、价格口径与无未来函数原则

1. **双轨价格并行**：
   - **原始现货 OHLC**（来自 `TDX-01` 日线 CSV）：用于一切成交价撮合、现金扣减/回笼、分红金额计算与每日收盘市值估值，保证账面份额与现金贴近真实盘口。
   - **前复权连续可比 OHLC**（在原始日线上叠加 `split_events` 与 `dividend_events` 计算）：用于 55 日突破高点、20 日离场低点与 `ATR20` 指标计算，消除除权除息价格断层引发的假突破/假破位。
2. **严格截止 `T-1` 信号纪律**：
   - 交易日 `T` 的所有路由态、突破/破位触发线、建网 `ATR20` 步长均严格基于截至 `T-1` 收盘可知的信息计算；
   - 触发价在日 `T` 与原始现货价比较时，使用同一复权基准映射至日 `T` 现货价格空间（对于最新复权因子为 `1.0` 的前复权序列，日 `T` 现货价与前复权价一致，无需二次换算）。

## 三、每日 4 步确定性处理顺序

对每一个交易日 `T`（按自然交易日升序推进），引擎严格按以下 4 步顺序串行执行，禁止乱序或跨步回溯：

### Step 1｜除息再投（及盘前份额拆分处理）

在开盘撮合前，依次按标的代码升序处理当日生效的公司行为事件：

1. **份额拆分（`split_events`）**：
   - 若当日等于某标的拆分生效日 `effective_date`（如 `512480.SH` `factor = 0.5`，1 份拆为 2 份）且账户持有该标的份额 `shares > 0`：
     - 持仓份数更新为 `shares_new = round(shares / factor)`；
     - 单位持仓成本更新为 `avg_cost_new = avg_cost * factor`；
     - 若标的处于已建网状态，网格基准价 `anchor_price` 与各档触发价同步乘以 `factor`（步长比例 `step_locked` 保持不变）。
2. **现金分红与除息再投（`dividend_events` & `dividend_reinvest: true`）**：
   - 若当日等于某标的现金分红除息日 `ex_date` 且盘前持仓 `shares > 0`：
     - 应得现金分红：`div_cash = shares * cash_per_unit`，先全额计入账户现金 `cash += div_cash` 并登记分红流水；
     - 若 `dividend_reinvest == true` 且当日该标的正常交易（`open > 0`）且当前路由非 `TRAP_OFF`：
       - 计算可再投整手份数：在保留手续费约束下计算最大整手 `reinvest_shares = floor(div_cash / (open * (1 + commission_rate)) / lot_size) * lot_size`；若计算所得总支出 `reinvest_shares * open + fee > div_cash`（如触发 `min_commission = 0.1`），则逐手递减直至 `notional + fee <= div_cash`；
       - 若 `reinvest_shares >= lot_size`：以当日 `open` 成交买入 `reinvest_shares` 份，扣除成交额与手续费 `fee = max(notional * commission_rate, min_commission)`，记录为 `DIVIDEND_REINVEST` 成交；余零资金自然留存账户现金；
       - 若分红金额不足买入 1 手（100 份）或标的处于 `TRAP_OFF`：不执行再投买入，分红现金全额留存账户现金。

### Step 2｜开盘路由切换 / `TRAP_OFF` 强平（以当日 `open` 执行）

按标的代码升序检查截至 `T-1` 收盘已确定的目标路由态 `target_regime` 与标的当前策略运行态 `active_regime`：

1. **`TRAP_OFF` 强平（最高优先级）**：
   - 若 `target_regime == "TRAP_OFF"`：
     - 若当前持仓 `shares > 0`，立即以当日 `open` 全额卖出平仓，回笼现金 `shares * open - max(shares * open * commission_rate, min_commission)`，记录 `TRAP_OFF_LIQUIDATION` 成交；
     - 清空该标的策略状态（海龟状态 / 网格锚价与档位），将 `active_regime` 置为 `TRAP_OFF`。
2. **跨路由态切换（`target_regime != active_regime`）**：
   - 若原运行态持有仓位（`shares > 0`）：先以当日 `open` 全额平仓并计提手续费，记录 `REGIME_SWITCH_EXIT` 成交，重置旧策略内部状态，保证海龟与网格账务彼此独立不混杂；
   - 更新 `active_regime = target_regime`；
   - 根据新路由态初始化：
     - 切入 `RANGE_GRID`：执行网格开网初始化——
       - 计算锁定步长：`raw_step = ATR20_{T-1} / close_{T-1}`，`step_locked = min(max(raw_step, step_min), step_max)`（截断于 `[0.02, 0.05]`）；
       - 锁定基准价：`anchor_price = open_T`；
       - 计算单标的预算：`budget = min(prev_nav * sector_max_weight, available_cash)`，单份预算 `slice_budget = budget / total_slices`（`total_slices = 5`）；
       - 以当日 `open_T` 建仓 `initial_slices = 2` 份（目标金额 `2 * slice_budget`，考虑手续费后向下取整至 `lot_size = 100` 份），记录 `GRID_INIT_BUY` 成交；
       - 生成对称价格档位表：向下 `1..4` 档买入价 `anchor_price * (1 - k * step_locked)`，向上 `1..4` 档卖出价 `anchor_price * (1 + k * step_locked)`（`k = 1, 2, 3, 4`）。
     - 切入 `TREND_UP`：进入海龟空仓监控态，等待 Step 3 盘中突破触发。
     - 切入 `TRANSITION` / `UNRATED`：保持空仓观察，不新开仓。

> **同日买入锁定原则（防日内回转幻觉）**：Step 1 与 Step 2 当日新买入的份额记为当日新增仓位，**不参与当日 Step 3 的卖出撮合**，确保日频回测不依赖未知的盘中先后路径且兼容场内 ETF T+1 约束。

### Step 3｜盘中海龟 / 网格触价撮合（基于当日 `open / high / low`）

按标的代码升序对已激活策略的行业 ETF 执行盘中触价判定（均仅消费 `T-1` 已定格指标）：

#### 3.1 海龟策略（`active_regime == "TREND_UP"`）

- **通道计算（基于前复权序列，截止 `T-1`，不含当日 `T`）**：
  - 入场触发价：`entry_price = max(high[T-55 : T-1])`（若历史样本不足 `entry_lookback = 55` 日，则不触发入场）；
  - 离场触发价：`exit_price = min(low[T-20 : T-1])`（若历史样本不足 `exit_lookback = 20` 日，则不触发离场）。
- **空仓时检查入场**：
  - 触发条件：`high_T >= entry_price`；
  - 确定性成交价：`fill_price = max(open_T, entry_price)`（向上跳空直接按 `open_T` 成交）；
  - 目标买入金额：`target_notional = min(prev_nav * sector_max_weight, available_cash)`；
  - 考虑手续费后向下取整至 `lot_size = 100` 份；若可买份数 `>= 100`，成交并记录 `TURTLE_ENTRY_BUY`（当日不触发离场卖出）。
- **持仓（且为 `T-1` 及之前已有持仓）时检查离场**：
  - 触发条件：`low_T <= exit_price`；
  - 确定性成交价：`fill_price = min(open_T, exit_price)`（向下跳空直接按 `open_T` 成交）；
  - 全额卖出该标的全部持仓，扣除手续费，记录 `TURTLE_EXIT_SELL`。

#### 3.2 网格策略（`active_regime == "RANGE_GRID"`）

- 维持建网时锁定的 `anchor_price`、`step_locked`、`slice_budget` 与当前持仓档位计数 `slices_held`（范围 `0 .. total_slices`）；
- 若当日刚在 Step 2 完成建网初始化（当日已有 `GRID_INIT_BUY`），按确定性口径跳过当日 Step 3 反向卖出，仅允许在极端下跌触及下方买入档时按规则判定（或在 `1t03` 中明确建网当日仅完成开盘初始化、自次交易日起开始盘中网格撮合，二者择一由 `1t03` 单测锁定；**推荐基线**：建网当日完成 `GRID_INIT_BUY` 后自 `T+1` 起参与盘中网格档位撮合，彻底避免建网当日 `open` 与 `high/low` 顺序歧义）。
- **常态盘中触价撮合（`T` 日持有已激活网格）**：
  - **触发格位**：基于上日收盘所在格位 `current_grid_idx`（初始建网为 `0`，向下买一档 `-1`、向上卖一档 `+1`，边界 `[-4, +4]`）：
    - 下一买档价：`buy_trigger = anchor_price * (1 + (current_grid_idx - 1) * step_locked)`（需 `current_grid_idx - 1 >= -grid_levels_each_side` 且 `slices_held < total_slices`）；
    - 下一卖档价：`sell_trigger = anchor_price * (1 + (current_grid_idx + 1) * step_locked)`（需 `current_grid_idx + 1 <= grid_levels_each_side` 且可卖持仓 `sellable_shares > 0`）。
  - **向下触价买入**：当 `low_T <= buy_trigger` 时，成交价 `fill_price = min(open_T, buy_trigger)`，按单份预算 `min(slice_budget, available_cash)` 向下取整至 100 份整手买入，成交后 `slices_held += 1`、`current_grid_idx -= 1`；若单日深跌连续穿透多档，允许按档位由高到低逐档触发直至达到当日 `low_T` 或用尽 `total_slices` / 现金。
  - **向上触价卖出**：当 `high_T >= sell_trigger` 时，成交价 `fill_price = max(open_T, sell_trigger)`，卖出 1 份对应整手股数（若 `slices_held == 1` 则清出全部剩余可卖持仓），成交后 `slices_held -= 1`、`current_grid_idx += 1`；若单日急涨连续穿透多档，按档位由低到高逐档触发直至达到当日 `high_T` 或可卖份额清零。
  - **单日同时触及买卖双边时的确定性决胜规则**：若单根日 K 线同时满足 `low_T <= buy_trigger` 且 `high_T >= sell_trigger`（宽幅震荡日线无法分辨先高后低还是先低后高）：
    - 先判断 `open_T` 相对 `buy_trigger` / `sell_trigger`：若开盘直接跳空越过某一侧触发价，则优先执行跳空侧；
    - 否则按保守确定性次序处理：**优先执行卖出旧仓（仅限 `T-1` 可卖份额），再执行买入档位（新增份额当日不可卖）**，确保结果唯一、无路径随机性且不违反 T+1 约束。

### Step 4｜收盘净值核算与资金守恒校验（以当日 `close` 估值）

交易日 `T` 所有撮合结束后，以各标的当日原始收盘价 `close_T` 核算账户收盘状态：

1. **持仓市值**：`market_value_T = sum(shares_i * close_{i,T})`（停牌或缺失当日价格时沿用最近有效收盘价并在日志中显式标注）；
2. **总资产与单位净值**：
   - `nav_T = cash_T + market_value_T`
   - `unit_nav_T = nav_T / initial_capital`
3. **绩效与风险指标**：
   - 当日收益率：`daily_return_T = nav_T / nav_{T-1} - 1`
   - 累计收益率：`cum_return_T = unit_nav_T - 1`
   - 历史峰值与动态回撤：`peak_nav_T = max(peak_nav_{T-1}, nav_T)`，`drawdown_T = nav_T / peak_nav_T - 1`
   - 基准对照：同步计算 `159330.SZ` 同期前复权/分红再投累计收益率及组合相对超额（`cum_return_T - benchmark_cum_return_T`）；
4. **账务守恒自检**：
   - 校验每笔买入后 `cash >= 0`、所有持仓 `shares >= 0` 且均为 `lot_size`（100 份）整数倍（拆股后非整手零股在清仓时允许一次性卖出）；
   - 校验单日净值增量等于「持仓市值变动 + 现金净流入（卖出净额 - 买入总支出 + 分红现金）」，绝对误差须 `< 1e-6`。

## 四、确定性与边界异常处置原则

- **标的遍历顺序**：所有涉及共享现金池的操作（Step 1 再投、Step 2 开盘建网、Step 3 盘中买入）统一按标的代码字母序（`159622.SZ`, `510720.SH`, `512400.SH`, `512480.SH`, `512880.SH`, `515790.SH`）遍历，消除字典遍历顺序差异。
- **最小手续费与资金不足处理**：计算任意买入/再投份数时，必须同时检验 `shares * fill_price + max(shares * fill_price * commission_rate, min_commission) <= available_cash`，不足时每次减少 1 手（100 份）直至满足或放弃本次买入，严禁出现负现金。
- **数据缺失中止**：若上游配置文件损坏或任一观察池标的缺少本地 `TDX-01` 日线 CSV，立即显式抛错中止，严禁静默跳过或使用网络行情替代。
