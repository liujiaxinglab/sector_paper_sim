# 实验复现与真实事件抽核

## 实验身份与恢复门禁

每个输出目录的 `experiment_manifest.json` 描述一个不可变实验，记录实验 ID、模拟起算日、本金、账户和策略参数摘要（`account_strategy_config_summary`）、配置文件参考 SHA-256、程序版本/提交号/源码 SHA-256、规则版本（`RULES_VERSION` 及其摘要 `rules_sha256`），以及初始化输入版本。规则版本当前为 `2.0.0`；撮合规则发生变化时同步更新版本号与源码。

每个模拟交易日写入 `daily_inputs/inputs_YYYYMMDD.json`。清单记录当日运行日期、formal/replay 模式、行情滞后放行开关、前瞻评价起点、实际使用的 TDX 批次文件名与 SHA-256、BS-01 日历文件、公司行为台账的 `as_of`/Schema/文件哈希、`regime_history.json` 的 Schema/哈希及观察池文件哈希。清单只引用 QuantData 与 sector_radar 文件，不复制行情原始数据。

`state.json` 保存实验 ID、manifest 哈希和按日期顺序汇总的每日输入清单哈希链。续跑前仅校验真正影响撮合的核心策略/费率/起算参数（`simulation_start_date`、`initial_capital`、`account_strategy_config_summary`）、程序源码与版本（`program_version`/`program_commit`/`program_source_sha256`）、规则版本（`rules_version`/`rules_sha256`）和已提交日期的输入清单；不再将 Markdown 文档（`01_撮合与切换确定性规则.md`）或配置文件格式/非撮合字段计入续跑阻断。回放初始化后可以在新的交易日切换为 formal 前瞻；每一天的运行模式写入该日输入清单。日常更新的行情批次、台账水位和路由历史只作为当日输入版本记录，不参与不可变实验配置比较。

## 全量重建与既有账本

`--from-scratch` 先在内存中从起算日完整重放，再比对 NAV、成交、最新报告、每日日快照、每日输入清单和 checkpoint。已有文件只有在重建内容一致时才保留；遇到不同配置、输入版本、报告或快照时，在发布前明确失败，原有输出不变。需要采用变化后的实验时，使用新的输出目录，并保留旧目录作为原实验档案。

没有 manifest 的旧账本不能直接续跑。可以使用 `--from-scratch` 对旧账本做完整重放；所有既有结果一致后，程序才补充 manifest、每日输入清单及 state 身份。若无法完全重现，保留原目录，并在新输出目录开始新实验。

## 首个真实触发事件抽核清单

截至本文件编写时，下列策略事件尚未由真实前瞻行情触发，状态为“待首次真实事件抽核”。合成测试验证规则边界，不等同于真实行情覆盖。

| 事件 | 状态 | 首次触发时核对 |
| --- | --- | --- |
| 路由切换并清仓 | 待首次真实事件抽核 | T 日目标路由、T+1 生效时点、成交日/价格/数量；对应 `trades.csv`、`nav_daily.csv` 与当日输入清单中的 regime hash |
| 分红到账与复投 | 待首次真实事件抽核 | 台账事件、持仓股数、到账金额、复投股数及佣金；对应 `trades.csv`、`nav_daily.csv` 与公司行为台账版本 |
| 海龟入场与止损 | 待首次真实事件抽核 | 突破触发价、下一交易日成交、止损信号和成交约束；对应 `trades.csv`、`nav_daily.csv` 与当日 TDX 批次 |
| 停牌或缺失行情 | 待首次真实事件抽核 | 使用前收估值、未成交处理、恢复交易后的估值衔接；对应 `nav_daily.csv` 和当日 TDX 批次 |

每次抽核记录交易日期、事件依据、输入清单路径、涉及账户与标的、逐笔成交及净值对账结论。不得将合成 fixture 结果标记为真实行情已覆盖。
